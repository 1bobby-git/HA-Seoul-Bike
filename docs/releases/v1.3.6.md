# Seoul Bike v1.3.6

## 연결 끊김 재시도 플랫폼 이식성

`[Errno 104] Connection reset by peer`의 오류 번호는 운영체제마다 다릅니다. `ECONNRESET`는 Linux에서 104이지만 Windows에서는 10054입니다. 기존 재시도 판정은 이 숫자 집합만으로 일시적 연결 오류를 구분해서, errno 값이 다른 환경에서는 실제 연결 끊김을 재시도하지 못하고 곧바로 오류로 전달할 수 있었습니다.

- 연결 끊김 재시도 판정을 errno 숫자가 아니라 예외 종류(`ConnectionError` 계열)로 처리합니다. `ConnectionResetError`·`ConnectionAbortedError`·`BrokenPipeError`·`ConnectionRefusedError`는 플랫폼 errno 값과 무관하게 일시적 오류로 취급합니다.
- 기존 동작은 그대로 유지합니다. 조회용 GET과 이동 경로/이용권/실시간 대여소 POST만 재시도하며, 최대 3회 시도·기본 0.5초/1초 지연·시도당 10초 시간 제한, HTTP 500/502/503/504 제한 재시도와 `Retry-After` 처리도 변경하지 않았습니다.
- 로그인 POST, 인증/TLS 오류, 잘못된 JSON은 계속 재시도하지 않습니다. HA 종료·재로드 취소 신호도 즉시 전달합니다.

## 테스트 이식성

- 소스 파일을 읽는 테스트가 기본 인코딩을 사용해 UTF-8이 아닌 로캘(예: Windows cp949)에서 실패하던 문제를 수정했습니다. UTF-8로 명시해 읽습니다.
- 플랫폼 errno와 무관하게 연결 끊김이 재시도되는지 확인하는 회귀 테스트를 추가했습니다.

## 유지되는 항목

로그인·쿠키 처리·데이터 파서는 `site_api.py`에 그대로 보존했습니다. `api.py`의 공개 경로, 엔티티 ID, 사용자 설정, 3단계 폴링 주기는 유지됩니다.

## 검증과 설치

배포 워크플로는 전체 단위 테스트, HACS, Hassfest 검증이 모두 성공한 main 커밋만 릴리스합니다. 네트워크 테스트는 합성 응답과 로컬 TCP 강제 연결 종료를 사용하며 실제 따릉이 계정은 사용하지 않습니다. ZIP 무결성과 manifest/태그 버전을 확인하고 SHA256SUMS.txt를 제공합니다.

HACS에서 **1.3.6으로 업데이트한 뒤 Home Assistant를 재시작**하세요. 통합 삭제나 재등록은 필요하지 않습니다. 설치 ZIP의 `custom_components/seoul_bike`를 사용하는 수동 설치도 가능합니다. 문제 발생 시 HACS에서 **1.3.5**로 되돌린 뒤 재시작할 수 있습니다.

실제 사용자 HA의 설치·재시작 및 로그인 후 운영 갱신은 이번 저장소 배포 검증에 포함되지 않습니다.
