# Seoul Bike v1.4.0

## 계정별 세션

1.3.6까지는 모든 계정이 Home Assistant 공용 HTTP 세션의 쿠키 저장소를 같이 썼습니다. aiohttp는 저장소의 쿠키로 같은 이름의 `Cookie` 헤더 값을 덮어쓰므로, 한 계정이 다시 로그인하면 다른 계정의 요청에도 그 계정의 `JSESSIONID`가 실렸습니다. 그 결과 다른 계정의 대여 상태·이용 내역·즐겨찾기가 보이고 즐겨찾기 엔티티가 바뀔 수 있었습니다(서버의 데이터는 바뀌지 않음).

- 계정(설정 항목)마다 별도의 쿠키 저장소를 가진 세션을 씁니다. 항목을 언로드하면 Home Assistant가 세션을 정리합니다.
- 계정이 하나라면 동작은 같습니다. 요청은 지금처럼 저장된 쿠키로 시작합니다.

## 로그인 실패 처리

- 패스워드가 거부되면(`login_failed`) 재인증을 요청하고, 재인증하기 전까지 다시 로그인하지 않습니다. 1.3.6까지는 60초마다 거부된 패스워드로 다시 로그인했습니다.
- 재로그인 중 연결 오류·시간 초과·예상하지 못한 응답은 패스워드 오류로 보지 않습니다. 이전 값을 유지하고 다음 주기에 다시 시도하며, 시작할 때는 설정을 다시 시도합니다(재인증 요청 없음).
- 대여 상태 요청이 로그인 페이지(`/login.do`)로 리디렉트되면 로그아웃으로 보고 다시 로그인합니다. 로그인 직후의 확인 요청이 로그인 페이지로 돌아오면 패스워드 거부로 처리해, 같은 패스워드를 다시 보내지 않습니다.
- 새로 고침 버튼의 재로그인에도 같은 규칙을 적용합니다.

## 즐겨찾기 보존과 일시 오류

- 이용 내역이 로그인 페이지로 오면 이전 즐겨찾기·이용 내역·마이페이지 값을 유지합니다. 1.3.6에서는 이 결과의 즐겨찾기가 비어 있어, 5분 주기 갱신을 건너뛰는 다음 주기에 즐겨찾기 센서·버튼·기기가 지워졌다가 다시 생겼습니다.
- 이용 내역 응답이 비어 있으면 일시 오류로 처리합니다(재인증 요청 없음). 이용 내역 새로 고침 버튼도 같습니다.
- 이용권 만료일 보조 페이지(`/myLeftPage.do`)가 실패해도 전체 갱신이 실패하지 않고 이전 만료일을 유지합니다. 정기 갱신과 마이페이지 새로 고침 버튼에 모두 적용됩니다.

## 주변 추천 센서 (새 기능)

README의 주변 추천 센서는 예전 설정 방식으로 대여소 목록(`station_ids`)이 저장된 항목에만 생겼습니다. 지금의 설정 화면은 이 값을 저장하지 않아 새 항목에는 생기지 않았습니다.

- 내 위치 엔티티를 설정하면 기존 센서 3개를 만듭니다: `주변 대여 가능 자전거 (전체)`, `주변 추천 대여소 대여 가능 자전거`, `주변 대여소 목록`. unique_id와 엔티티 ID는 기존 센서와 같습니다.
- 기준 위치·반경(500m)·최소 자전거 수(1대)·추천 개수(5곳)는 기존 계산을 그대로 씁니다. 대여소 실시간 목록은 이미 매 주기 받고 있어 요청이 늘지 않습니다.
- 대여소 실시간 목록을 받지 못한 주기에는 0대로 바꾸지 않고 이전 주변 추천 값을 유지합니다.
- 위치 엔티티의 `latitude`·`longitude` 속성을 쓰고, 속성이 없으면 `위도,경도` 형식 상태를 씁니다(즐겨찾기 거리 센서와 같은 규칙). 위치 엔티티를 찾을 수 없거나 좌표가 없으면 지금처럼 Home Assistant 집 위치를 기준으로 하고, 센서의 `상태` 속성에 이유(`location_entity_not_found`, `location_no_coords`)를 표시합니다.
- 위치 엔티티를 지우면 이 센서와 빈 기기를 정리합니다. 대여소별 센서·버튼은 지금처럼 `station_ids`가 있는 항목에만 있습니다.

## 설정 화면

- 재인증·옵션 화면은 저장된 패스워드를 기본값으로 브라우저에 보내지 않습니다. 아이디를 그대로 두고 패스워드 칸을 비우면 저장된 값을 씁니다. 아이디를 바꾸면 패스워드를 다시 입력해야 합니다(다른 계정에 저장된 패스워드를 보내지 않음).
- 내 위치 엔티티를 지울 수 있습니다(기본값 대신 제안값으로 표시). 재인증 화면에서 바꾼 위치도 옵션에 저장된 위치와 함께 바로 적용됩니다.
- 재인증 완료·실패 문구를 추가했습니다. 로드된 항목은 재인증 뒤 한 번만 다시 불러옵니다.

## 그 밖의 수정

- 레거시 항목의 바이너리 센서 설정이 동기 함수를 `await`해 `TypeError`로 중단되던 문제를 고쳤습니다.
- 레거시 대여소 센서와 버튼이 첫 갱신에서 같은 unique_id로 다시 등록되며 남기던 오류 로그를 없앴습니다.
- 이동 경로 센서의 `경로 좌표` 속성을 기록기(recorder)에 저장하지 않습니다.
- 재로그인 쿠키를 옵션에 남은 이전 쿠키까지 갱신합니다.
- 쿠키 저장소를 aiohttp 4에서도 동작하는 방식(`yarl.URL`)으로 읽습니다.

## 유지되는 항목

로그인·쿠키 처리·데이터 파서의 원본(`site_api.py`), `api.py`의 공개 경로, 엔티티 ID와 unique_id, 사용자 설정 항목, 3단계 폴링 주기(60초·5분·30분), 네트워크 재시도 정책, 즐겨찾기 조회 실패 처리, 자전거 수 계산은 바꾸지 않았습니다.

## 검증과 설치

배포 워크플로는 전체 단위 테스트, HACS, Hassfest 검증이 모두 성공한 main 커밋만 릴리스합니다. 테스트는 합성 응답을 사용하며 실제 따릉이 계정은 사용하지 않습니다. ZIP 무결성과 manifest/태그 버전을 확인하고 SHA256SUMS.txt를 제공합니다.

HACS에서 **1.4.0으로 업데이트한 뒤 Home Assistant를 재시작**하세요. 통합 삭제나 재등록은 필요하지 않습니다. 문제 발생 시 HACS에서 **1.3.6**으로 되돌린 뒤 재시작할 수 있습니다. 1.3.6으로 되돌리면 1.4.0이 위치 엔티티 항목에 만든 주변 추천 센서 3개는 `사용할 수 없음`으로 남습니다. 필요 없으면 엔티티 설정에서 삭제하세요.

실제 사용자 HA의 설치·재시작 및 로그인 후 운영 갱신은 이번 저장소 배포 검증에 포함되지 않습니다.
