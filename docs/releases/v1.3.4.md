# Seoul Bike v1.3.4

## 연결 끊김 복구

`[Errno 104] Connection reset by peer`는 통신 중 연결이 끊어졌다는 뜻이며, 이 로그만으로 따릉이 서버와 중간 네트워크 중 어느 쪽이 원인인지는 확정할 수 없습니다. 기존 요청 계층에는 일시적인 연결 오류를 복구하는 재시도와 요청별 시간 제한이 없었습니다.

- 조회용 GET 및 이동 경로/이용권/실시간 대여소 POST에 최대 3회 시도, 기본 0.5초/1초 지연, 시도당 10초 시간 제한을 적용합니다.
- HTTP 500/502/503/504도 제한적으로 재시도합니다. `Retry-After`가 5초를 초과하거나 해석 불가능하면 짧게 재시도하지 않고 오류를 전달합니다. HTTP 429도 즉시 반복하지 않습니다.
- 따릉이 응답 소켓을 유지하지 않도록 `Connection: close`를 사용합니다. HA의 공유 HTTP 세션은 유지합니다.
- 로그인 POST, 인증/TLS 오류, 잘못된 JSON은 반복하지 않습니다. HA 종료/재로드 취소 신호도 즉시 전달합니다.
- 연결 복구에 성공하면 원래 파싱 결과로 갱신하고, 모두 실패하면 기존 `UpdateFailed` 경로로 오류를 전달합니다. 장애를 숨기거나 오래된 값을 새 데이터로 반환하는 변경은 하지 않았습니다.

서버의 지속적인 장애 자체를 해결하는 업데이트는 아닙니다. 오류가 계속되면 따릉이 서비스와 HA 네트워크 상태를 함께 확인해야 합니다.

## 유지되는 항목

기존 로그인·쿠키 처리·데이터 파서는 `site_api.py`에 내용 변경 없이 보존했습니다. 다른 모듈이 사용하는 `api.py`의 클래스/도우미 경로, 엔티티 ID, 사용자 설정, 3단계 폴링 주기는 유지됩니다.

## 검증과 설치

배포 워크플로는 전체 단위 테스트, HACS, Hassfest 검증이 모두 성공한 main 커밋만 릴리스합니다. 네트워크 테스트는 합성 응답 및 로컬 TCP 강제 연결 종료를 사용하며 실제 따릉이 계정은 사용하지 않습니다. ZIP 무결성과 manifest/태그 버전도 확인하고 SHA256SUMS.txt를 제공합니다.

HACS에서 **1.3.4로 업데이트한 뒤 Home Assistant를 재시작**하세요. 통합 삭제나 재등록은 필요하지 않습니다. 설치 ZIP의 `custom_components/seoul_bike`를 사용하는 수동 설치도 가능합니다. 문제 발생 시 HACS에서 **1.3.3**으로 되돌린 뒤 재시작할 수 있습니다.

실제 사용자 HA의 설치·재시작 및 로그인 후 운영 갱신은 이번 저장소 배포 검증에 포함되지 않습니다.
